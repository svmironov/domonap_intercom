# Состояние соединений и диагностика

У каждого аккаунта есть диагностические датчики:

- Соединение SignalR: подключено или отключено.
- Регистрация SIP: нет сессии, зарегистрирована или не зарегистрирована.
- Регистрация внешнего SIP: отключена, зарегистрирована или не зарегистрирована.
- Последнее событие: время последнего прикладного события SignalR; ping его не обновляет.
- Последняя ошибка: компонент и код ошибки, с временем в атрибуте `last_error_at`.

SIP-сессия домофона создаётся на время звонка, поэтому `idle` между звонками
является обычным состоянием. Последняя ошибка сохраняется после восстановления
соединения; текущее состояние следует смотреть в датчике соответствующего
соединения. Датчики читают локальное состояние без дополнительных сетевых запросов
и обновляются с обычным интервалом опроса платформы sensor.

В Home Assistant доступна загрузка диагностики записи интеграции. Выгрузка
содержит только перечисленные состояния и время: без токенов, SIP-паролей,
адресов дверей и содержимого событий.

Список дверей загружается один раз при запуске аккаунта, со всеми страницами,
и используется всеми его платформами до перезагрузки записи интеграции.
Срока действия кеша и периодических запросов нет; открытие двери также не
обновляет список. Перезагрузка записи загружает список заново и создаёт
сущности для новых дверей. Ошибка первоначальной загрузки приводит к повторной попытке
настройки, а не к успешной настройке с пустым списком устройств.

Кнопки и сервисы открытия показывают ошибку при неудаче. После сетевого сбоя
интеграция пытается завершить звонок, начавшийся до открытия, и не завершает
новый звонок, пришедший во время запроса. Сетевые ошибки открытия не вызывают
автоматического повторного открытия реле.

REST и WebSocket используют проверку TLS-сертификатов. Ошибки сертификата
отображаются в диагностике как тип ошибки соединения; небезопасного обхода
проверки сертификатов нет.
